## 工作流是什么

本文按当前工作流编辑器整理，更新于 2026 年 9 月 23 日。

工作流把一项任务拆成多个组件，用连线规定执行顺序，用 JSON 规定组件之间传递的数据。可以让 AI 完成分析，也可以设置变量、按规则选择路径、等待多路结果或请求人工确认。

**节点**是执行步骤；**输出分支**定义该步骤往哪里走、输出什么；**连线**把一个输出分支连接到下游节点。一个输出分支可以连接多个下游，这些路径按运行器调度执行，不保证同时运行。

例如，一条文档审查流程可以是：

```text
开始 → Agent 审查 → 数据变量 → 文本判断
                              ├─ 高风险 → 人工确认 → 系统通知 → 结束
                              └─ 其他   → 系统通知 → 结束
```

本文的 `step_review_1`、`step_left_1` 等是示例节点 ID。实际配置时，请点击属性面板的字段引用按钮，或把示例 ID 换成自己工作流中的 ID。上游输出使用 `{{input.节点ID.字段}}`；数据变量使用 `{{组件名称.变量名}}`，例如 `{{数据变量 1.result}}`。两种引用用途不同，不要混用。

## 快速开始：建立第一个流程

1. 进入“工作流”，点击新建，打开独立的画布编辑窗体。
2. 选择“开始”节点，在属性面板填写工作流名称并设置超时。工作流会使用自己的独立工作目录。
3. 添加一个 Agent 组件，填写执行内容，例如“查看项目说明，简要概括项目用途”。选择跟随当前模型或指定模型。
4. Agent 的唯一输出分支固定输出 `{"result":"AI 的完整回答"}`，无需填写判断条件或输出 JSON。需要提取结构化字段时，可在下游连接“AI 判断”组件。
5. 添加系统通知组件，设置标题“分析完成”，在内容中插入 Agent 的 `result` 字段。
6. 从开始节点的输出端口连到 Agent，再将 Agent 的输出分支连到通知组件。通知固定提供“发送成功／发送失败”分支；命中的分支没有连接下游时，当前路径结束。也可以分别连接结束组件，明确成功或失败结果。
7. 保存工作流，返回工作流列表发起运行。查看节点状态、运行日志和结果；若停在人工确认步骤，需要在运行记录中处理确认。

新建流程需要先手动保存。编辑已保存的流程时，编辑器每 30 秒尝试自动保存更改；不合法的配置不会保存。关闭编辑器前，确认顶部显示已保存。

## 画布操作与通用规则

| 操作或规则 | 说明 |
| --- | --- |
| 添加组件 | 点击画布左侧悬浮组件库中的图标，悬停查看组件名称。默认名称使用同类组件当前最大尾部序号加 1。 |
| 命名 | 同一工作流内的组件名称必须唯一，包括不同类型的组件。首尾空格不用于区分重名。 |
| 连线 | 从输出端口拖向下游输入端口。同一输出可连多个下游。开始节点也可连接多个入口。 |
| 选择多个节点 | Shift 追加选择，Ctrl/Cmd 切换选择，Alt 减选；也可在空白处框选。 |
| 移动与查看 | 拖动节点可视区域的任意位置移动节点（连线端口除外）；使用画布工具缩放或复位，也可按住空格拖动画布。 |
| 撤销与重做 | Ctrl/Cmd+Z 撤销；Ctrl/Cmd+Shift+Z 重做，Windows 也支持 Ctrl+Y。 |
| 保存校验 | 错误组件显示红色高亮框；手动保存时选中首个已定位的错误组件，修正后再次保存可更新或清除标记。 |
| 删除组件 | 属性面板删除按钮、批量删除和 Delete/Backspace 均需确认；相关连线一并移除。 |
| 流程限制 | 除数据变量组件外，节点必须能从开始节点到达；所有组件均不支持循环连线。命中分支未连接下游时，当前路径结束。 |

选择节点后，右侧属性面板显示组件配置及预计接收结构。预计结构来自**直接连接到此节点的输出分支**；它是设计时的定义，实际值在运行后产生。不同候选分支分别显示，不会合成一份虚构的数据。

## 开始组件：定义入口

开始组件是工作流的入口和全局配置入口，不调用 AI，也不生成业务数据。

**配置方法**：填写名称和说明、执行超时分钟数以及保存后是否启用。拖动开始节点的输出端口，连接一个或多个起始组件。

**用例**：一项报告需要“内容检查”和“格式检查”，可以把开始节点分别连接到两个 Agent，再用汇合组件接收两路结果。

这里的超时限制用于工作流执行；当流程只剩人工确认待办时，执行计时暂停，人工确认按自己的等待设置处理。

每次运行会记录工作流版本。编辑并保存后，后续新运行使用保存后的定义。正在查看的历史记录仍对应其运行版本。

## Agent 组件：让 AI 完成任务

Agent 用模型完成分析、编码、文档处理等任务。它根据执行内容开展工作，然后通过唯一的输出分支传递 `{"result":"AI 的完整回答"}`。需要按 AI 判断分流时，请使用“AI 判断”组件。

### 如何配置

- **执行内容**：写明任务、输入含义与预期结果。可插入上游字段或工作流变量。
- **模型**：跟随当前连接，或选择指定模型。选择指定模型时，运行将使用该节点的模型配置。
- **模式、最大步骤和权限**：按任务设置编码、通用或文档模式，并选择所需步骤上限及权限。
- **输出分支**：保留一个分支并连接下游节点。任务成功后将完整回答放入 `result` 字段；任务失败时节点失败。

例如，审查组件回答“缺少必要审批记录”时，输出为：

```json
{
  "result": "缺少必要审批记录"
}
```

下游组件可用 `{{input.节点ID.result}}` 引用完整回答。即使 AI 回答本身是 JSON 文本，它仍作为 `result` 字符串传递；需要解析字段或按语义分流时，请使用“AI 判断”组件。Agent 不会再要求 AI 选择分支或填充预设的输出模板。

旧工作流在重新保存前仍按其原有的 Agent 分支配置运行。打开旧工作流、保留一个 Agent 输出分支并保存后，会改为上述固定输出格式。

新建 Agent 在输入到达后按其输入模式执行。需要保证多个上游的数据都已准备好时，建议在 Agent 前使用“等待全部上游”的汇合组件，不要依赖连线数量推断等待行为。

## 组件库：按用途选择组件

画布左侧悬浮组件库按“任务执行、数据处理、逻辑判断、流程控制”分类，组件按钮为纯图标，悬停显示名称，点击即可添加。组件库可收起，便于查看被面板遮挡的画布区域。

| 分类 | 组件 |
| --- | --- |
| 任务执行 | Agent、系统通知 |
| 数据处理 | 数据变量、汇合 |
| 逻辑判断 | AI 判断、文本判断、数值判断、布尔判断、集合判断、条件判断、Switch |
| 流程控制 | 人工确认、结束 |

### AI 判断：按自然语言选择路径

在“逻辑判断”中添加“AI 判断”，先连接上游，再选择一个直接上游字段作为**判断输入**，填写判断问题和各分支的自然语言条件。新建组件默认提供“符合条件”“不符合条件”“无法判断”三个分支；可增加分类分支，但“无法判断”分支不能删除。模型只返回分支 ID 和简短理由，不生成分支输出内容。

运行器校验模型返回的分支 ID，并固定输出 `{"result":原判断输入,"reason":"判断理由"}`，其中 `result` 保留原输入值和类型。输入缺失时进入“无法判断”分支；输入含糊或信息不足时，也应由模型选择该分支。模型返回未知分支或错误格式时，节点失败。已有的旧版 AI 判断节点继续沿用原配置；新建节点使用分类模式。

例如，Agent 查询上海今天的天气，输出 `{"result":"上海今天有阵雨"}`。AI 判断组件选择 `{{input.Agent节点ID.result}}`，判断问题填写“今天是否会下雨”，将“有雨”“无雨”“无法判断”分别连接到后续步骤。下游可继续引用天气原文 `{{input.AI判断节点ID.result}}` 和判断理由 `{{input.AI判断节点ID.reason}}`。其余文本、数值、布尔、集合、条件判断和 Switch 使用确定性规则，不调用 AI。

所有逻辑判断组件及旧版判断、路由节点在画布上均显示为菱形，输入端口位于左侧，输出端口沿右侧边缘排列。

### 各组件的分支规则

| 组件 | 分支与选择方式 |
| --- | --- |
| AI 判断 | 新建组件至少三个分支，包含固定的“无法判断”分支；AI 只选择分支并说明理由。 |
| Agent | 有且只有一个输出分支，固定输出 `{"result":"AI 的完整回答"}`，可连接多个下游。 |
| 数据变量、汇合 | 一个输出分支，完成后直接输出，无匹配条件。 |
| 文本／数值／布尔／集合判断、条件判断 | 固定“成立／不成立”两个分支，由配置的规则选择。 |
| Switch | 一个或多个固定匹配值分支，加一个默认分支。 |
| 人工确认 | 固定“批准／拒绝”两个分支，由人工决定或超时策略选择。 |
| 系统通知 | 固定“发送成功／发送失败”两个分支，由系统发送结果选择。 |
| 结束 | 没有输出分支，可单独设置最终结果 JSON。 |

以上每个输出分支均可连接多个下游。AI 判断的新分类模式自动传递输入和理由；其他可编辑输出内容的组件按其配置传递数据。

## 数据判断组件：按数据类型选择路径

判断组件不调用 AI。输入判断字段、运算符和比较值，支持固定值、上游字段引用（例如 `{{input.step_review_1.risk}}`）及变量引用（例如 `{{数据变量 1.risk}}`）。输入框提供已连接上游字段候选项。每次仅执行“成立”或“不成立”中的一条输出分支，两个分支均不能删除，但可改名、编辑 JSON 并连接多个下游。

| 组件 | 支持的规则 | 示例 |
| --- | --- | --- |
| 文本判断 | 等于、不等于、包含、开头是、结尾是、为空、非空；区分大小写 | `risk` 等于 `high` |
| 数值判断 | 等于、不等于、大于、大于等于、小于、小于等于 | `score` 大于等于 `80` |
| 布尔判断 | 等于、不等于；只接受 `true` / `false` | `approved` 等于 `true` |
| 集合判断 | 数组或对象为空／非空、数组包含元素、对象包含字段 | 数组包含 JSON 元素 `1` 或 `"high"` |

数值类型可接受合法数字字符串；空字符串不当作 0。集合可引用实际数组／对象，或输入 JSON。字段不存在、类型错误时节点失败，不会误走“不成立”分支。文本“为空”只匹配空字符串，不代表字段缺失或 null。复杂数组元素按 JSON 结构比较。

## 条件判断组件：组合多个规则

添加多条规则，每条规则独立选择数据类型、字段、运算符和比较值。选择“全部满足（AND）”或“任一满足（OR）”，最多 50 条。所有规则都会检查，任意字段缺失或类型错误都会使节点失败。

**用例**：数值 `score >= 80` 且布尔 `approved == true` 时走“成立”，其余走“不成立”。需要混合 AND／OR 时，可串联多个条件判断组件。

## Switch 组件：按值选择多个分支

配置一个判断值，选择文本、数值或布尔类型，然后添加固定匹配值。每项对应一个输出分支；匹配值不能重复（数值 `1` 与 `1.0` 也属于重复）。只执行一个匹配分支，未命中时执行唯一默认分支。默认分支不能删除，匹配分支至少保留一个、最多 50 个。

**用例**：判断 `{{input.step_review_1.risk}}`，`high` 分支连接人工确认，`medium` 分支连接复核 Agent，默认分支连接通知。每个分支独立配置输出 JSON，下游只收到命中分支定义的数据。

组件库不再提供旧“路由”；已有流程中的旧路由和旧版状态判断仍可编辑、运行。新建流程请使用数据判断、条件判断或 Switch。

## 数据变量组件：按组件保存变量

数据变量组件按组件分别保存变量，不调用 AI，不进行分支条件判断。同名变量不会覆盖其他组件的值。

**配置方法**：添加变量，填写变量名和值。变量值可以是固定文字、上游字段引用，或包含引用的文本。后续节点通过 `{{数据变量 1.变量名}}` 使用变量。变量按列表顺序赋值，后面的赋值可引用本组件前面已经设置的变量。

例如两个组件都定义 `result`，分别使用 `{{数据变量 1.result}}` 和 `{{数据变量 2.result}}`。组件名称需要唯一；界面显示名称引用，保存时绑定稳定的组件 ID。在属性面板改名会同步更新引用。引用不要求是直接上游，但该组件必须先执行并完成相应赋值；未执行、已删除或缺少变量时会报错，不会读取其他组件的同名变量。

旧写法 `{{variables.result}}` 仅为兼容旧流程保留，仍采用全局变量后写覆盖的行为；新流程请从引用列表选择带组件名称的引用。

例如：

| 变量名 | 变量值 |
| --- | --- |
| `risk` | `{{input.step_review_1.risk}}` |
| `reportTitle` | `审查报告：{{input.step_review_1.title}}` |

设置完成后直接执行“设置完成”输出分支，可连接多个下游。新建组件默认输出为：

```json
{"result":""}
```

如果需要输出变量，请自行改为：

```json
{
  "risk": "{{数据变量 1.risk}}",
  "title": "{{数据变量 1.reportTitle}}"
}
```

**用例**：保存审查风险等级，供后面的条件判断；或把零散输入整理成通知标题和正文。

工作流变量目前按字符串保存，不会自动执行算术表达式或脚本。输出模板本身可包含 JSON 数字、布尔值、数组，也可直接引用上游对象以保留类型。新建数据变量组件仅保留一个输出分支；旧流程中没有输出分支的数据变量组件可以作为路径末端执行。

## 汇合组件：等待与组装多路结果

汇合组件不调用 AI，负责等待输入，并按用户配置的模板组装输出。它有且只有一个输出分支，可连接多个下游，**没有判断或匹配条件**。

### 选择汇合方式

- **等待全部上游**：每个直接上游节点都必须有分支实际到达此节点，之后才执行。适合报告需要同时用到多个结果的情况。
- **任一上游到达**：收到输入后即可被调度。此时不保证其他上游数据已经存在。模板引用尚未到达的数据会失败。

“全部”按不同的上游节点计数。同一个上游的两个互斥分支都连到汇合节点，不代表需要两条分支同时发生。反之，某个上游最终选择了不通向汇合节点的分支，就不会满足其输入等待条件。

### 配置输出

新建汇合组件的默认输出是 `{"result":""}`。空字符串在这里就是空字符串，不会由 AI 填充，也不会自动复制全部输入。

把需要的字段写进输出模板，或点击可引用字段插入。只有模板指定的字段会进入该输出 JSON：

```json
{
  "reviewResult": "{{input.step_left_1.result}}",
  "scoreResult": "{{input.step_right_1.result}}"
}
```

**用例**：两份检查结果分别带有 `result`，汇合后将其改名为 `reviewResult` 和 `scoreResult`。下游收到的是这份组装结果，不会额外套一层节点 ID，也不会自动加入未配置的输入字段。

## 人工确认组件：等待人工决定

人工确认组件用于需要人做决定的步骤。仅当前路径等待，其他路径继续执行；多个确认节点可分别处理。在运行记录中选择具体节点，可填写可选备注，再批准或拒绝。记录会保存决定、时间和备注，重复提交不会重复执行下游。

**配置方法**：填写确认标题、内容以及批准／拒绝按钮名称。标题和内容可引用上游字段、数据变量。组件固定两个输出分支：第一个批准、第二个拒绝，不提供匹配条件，也不能增删。每个分支独立配置 JSON（默认 `{"result":""}`），可连接多个下游。

| 等待方式 | 行为 |
| --- | --- |
| 一直等待（默认） | 不设置人工确认截止时间，直到人工处理或取消运行。 |
| 等待指定时长 | 从节点开始等待时计时，以分钟设置，可填小数，最长一年。 |
| 等待至指定时间 | 在本地时区选择日期时间，保存为绝对时间；已过期则立即超时。 |

有限等待可以选择超时后进入拒绝分支，或结束整个流程并标记失败。超时会记录为“超时”，不会记为人工批准。

流程只剩人工确认待办时，普通执行超时计时暂停；恢复执行后继续计算剩余执行时间。其他路径仍在运行时，执行超时继续生效。纯等待状态可在应用重启后继续处理，有限等待的截止时间不会重置，过期会在重启后处理；应用关闭期间不执行后台任务。恢复确认使用本次运行的原始工作流版本。

例如，确认内容可以写为：

```text
本次审查风险为 {{数据变量 1.risk}}。
原因：{{input.step_judge_1.reason}}
是否继续执行发布准备？
```

批准分支连接后续处理，拒绝分支连接通知或失败结束。分支需要传递的数据，应在对应输出 JSON 中显式配置。

**用例**：高风险审查结果需要负责人确认后，才能触发下一步操作。

## 系统通知组件：显示桌面通知

系统通知组件将指定标题和正文交给系统通知服务，不调用 AI。

**配置方法**：填写标题和正文，可引用工作流变量及直接上游数据。例如标题为“报告已完成”，正文为 `{{input.step_report_1.result}}`。

通知固定“发送成功”和“发送失败”两个分支，由实际发送结果选择，不提供匹配条件，也不能增删。各分支独立配置 JSON，默认 `{"result":""}`，可引用上游字段和数据变量，且可连接多个下游。系统不支持通知、通知服务不可用或发送异常时走失败分支，运行记录保留错误原因。成功只表示通知已提交，不代表用户已阅读。

**用例**：报告完成、审批被拒绝或检查失败时通知用户。系统通知是否可见还取决于操作系统通知设置；节点成功表示通知已提交，不表示用户已经阅读。

## 结束组件：明确路径或流程结果

结束组件没有输出分支。分别设置结束状态、结束范围、摘要和可选的最终结果 JSON。

| 结束范围 | 行为 |
| --- | --- |
| 当前路径（默认） | 结束这一条路径，其他路径继续；全部路径完成后，只要有失败结束路径，流程最终记为失败。 |
| 整个工作流 | 按所选成功／失败状态立即结束工作流，停止其他运行任务、移除排队任务，并清理人工确认待办。 |

摘要供人阅读，支持上游字段和数据变量引用。最终结果 JSON 用于保存业务数据，支持插入引用、自动校验及格式化，在运行记录中独立显示；不填写时不会自动把摘要作为输出数据。多个路径的结果分别保留在对应结束节点记录中。

例如摘要填写“审核完成”，最终结果可以填写 `{"risk":"{{数据变量 1.risk}}"}`。需要失败后仍完成其他处理时选择“当前路径”；明确要停止整个流程时选择“整个工作流”。

## 旧版组件兼容说明

已有工作流可能包含旧版判断组件。它检查此前节点是否执行成功或失败，再按结果进入对应分支，不调用 AI。旧路由和旧状态判断仅为兼容已有流程保留，组件库不再提供路由入口。新流程使用文本、数值、布尔、集合判断、条件判断或 Switch。

## 输出内容：JSON、固定值与引用

所有组件的分支编辑区统一称为“输出内容”，填写后必须是有效 JSON。修改时自动校验，错误会显示在编辑框下方并阻止保存。“格式化”按钮整理缩进，不改变字段值与引用表达式；无法解析时保留原文。

| 引用方式 | 含义 |
| --- | --- |
| `{{input.step_review_1.result}}` | 从指定直接上游的实际输出读取字段。 |
| `{{input.step_review_1.meta.author}}` | 读取嵌套字段。 |
| `{{input.step_review_1.items.0}}` | 读取数组第一个元素，序号从 0 开始。 |
| `{{数据变量 1.risk}}` | 读取“数据变量 1”组件的 risk 变量，按组件区分同名变量。 |
| `{{input.result}}` | 省略来源的简写。输出模板中若多份输入都含该字段，来源不唯一，会报错；建议使用完整来源。 |

引用表达式在 JSON 编辑器里要放进双引号：

```json
{
  "result": "{{input.step_review_1.result}}",
  "details": "{{input.step_review_1.details}}",
  "message": "审查结论：{{input.step_review_1.result}}"
}
```

当整个字段值是引用时，程序保留被引用值的实际类型，因此 `details` 可输出对象或数组；带有“审查结论：”这样的文字前缀时，结果是字符串。程序会正确处理引号、反斜杠和换行，无需手动替换 JSON 原文。

编辑 JSON 对象时，点击“插入”按钮：若光标在字符串值内部，会在光标处插入引用；否则会新增一个字段。数组或基础值可直接编辑引用表达式。同名输出字段自动加编号，用户可自行改名。界面列出上游定义中的字段及嵌套对象，不自动提供“分支完整输出”字段，也不自动添加额外数据。

**不要写重复 JSON 字段名**。例如 `{"result":"A","result":"B"}` 会被拒绝，应改成两个不同名称。可编辑输出内容的分支支持合法的 JSON 对象、数组或基础值。固定值不会因非空而被拒绝。AI 判断分支中的空字符串由 AI 填写；其他组件的空字符串保持原样。Agent 的输出固定为 `{"result":"AI 的完整回答"}`。

### 固定值与 AI 生成值混合

```json
{
  "result": "通过",
  "score": 90,
  "enabled": true,
  "tags": ["reviewed"],
  "extra": null,
  "reason": "",
  "source": "{{input.step_review_1.title}}"
}
```

在 AI 判断分支中，仅 `reason` 交给 AI 生成，`source` 由程序读取上游，其他值保持不变。放在汇合、数据变量、判断、人工确认或通知组件时，`reason` 保持空字符串。合法的非空值不会再触发“必须是留空字符串或有效的引用表达式”的限制。

一个上游分支定义 `{"result":"通过"}`，下游预计接收的就是这份内容，不会自动变为 `{"节点ID":{"result":"通过"}}`。`input.节点ID.字段` 中的 ID 用于定位来源，不代表实际传输数据增加了外层对象。

## 用例一：审查、分流与人工确认

目标：让 AI 审查资料，高风险需人工确认，其余情况直接通知。

1. 添加 Agent“审查 1”，执行内容要求检查资料并说明风险。它的输出固定为 `{"result":"完整回答"}`。
2. 添加“AI 判断”组件并连接 Agent。在判断任务中引用 `{{input.step_review_1.result}}`，要求区分高风险和其他情况。
3. 配置“高风险”和“其他情况”两个输出分支；前者连接人工确认，后者连接通知。需要传递原因时，可在分支输出 JSON 中设置 `{"reason":""}`，由 AI 判断组件生成原因。
4. 人工确认的批准分支连接通知，拒绝分支连接失败结束；通知的成功和失败分支连接相应结束组件。
5. 保存、运行，分别用高风险和低风险资料验证路径。

`input` 引用直接上游节点 ID。Agent 的 `result` 始终是完整回答字符串；判断和结构化输出由后续“AI 判断”组件处理。

## 用例二：同名字段汇合，只输出部分数据

目标：内容检查和评分都使用 `result` 字段，最终只输出两个结果，不带中间说明。

开始节点分别连接两个检查组件；两者的完成分支都连接汇合组件。汇合方式选择“等待全部上游”。

第一路实际输出（`step_left_1`）：

```json
{"result":"通过","reason":"内容符合要求"}
```

第二路实际输出（`step_right_1`）：

```json
{"result":"90","detail":"评分明细"}
```

在汇合组件唯一的输出分支中填写：

```json
{
  "reviewResult": "{{input.step_left_1.result}}",
  "scoreResult": "{{input.step_right_1.result}}"
}
```

下游接收：

```json
{"reviewResult":"通过","scoreResult":"90"}
```

两个来源的 `result` 通过节点 ID 区分；`reason` 和 `detail` 没有被配置到输出中，因此不属于汇合的输出 JSON。可以把这一个输出分支同时连接到报告 Agent 和系统通知组件。

如果报告 Agent 还需要生成总结，可在执行内容中引用 `{{input.step_join_1.reviewResult}}` 和 `{{input.step_join_1.scoreResult}}`，要求它根据这两个值写出总结。它的回答会进入固定的 `result` 字段。

## 用例三：区分同名变量并按值分流

1. 添加“数据变量 1”，设置 `result = high`，连接“数据变量 2”，设置 `result = low`。
2. 在“数据变量 2”的输出内容中填写下面的 JSON。变量已经分别赋值，无需把两者都作为直接上游连接到消费者。
3. 连接 Switch，判断值填写 `{{数据变量 1.result}}`，类型选择文本，添加固定匹配值 `high`；该分支连接人工确认，默认分支连接通知。

```json
{
  "first": "{{数据变量 1.result}}",
  "second": "{{数据变量 2.result}}"
}
```

输出为 `{"first":"high","second":"low"}`，两个 `result` 不会互相覆盖。仅把数据变量放在画布上不会执行赋值；即使它不受入口可达性校验限制，引用前也需要保证它已执行。

## AI 错误日志：查看调用对话

AI 请求失败、响应解析失败，或模型返回内容未通过工作流校验时，应用会把对应 AI 对话写入“日志输出”。按 Ctrl/Cmd+Shift+L 打开，查找“AI 对话诊断”，结合任务 ID、模型名称以及工作流／节点上下文定位同一次调用。

日志包含：

- **错误原因**：例如服务请求失败、响应格式错误或输出校验失败。
- **请求对话**：该次请求实际携带的消息，包括用户任务、系统说明及已传入的上下文。
- **模型返回**：成功收到的模型回复；解析失败时尽可能保留原始响应；完全没有响应时会明确提示。

长对话按编号分段输出，超长内容会明确标记截断。API 凭据和媒体二进制数据会脱敏。用户取消请求不作为模型错误打印对话；普通 JSON 编辑错误也不会产生 AI 调用日志。

## 运行、排查与常见问题

从工作流列表发起运行，在运行记录中查看节点状态、分支选择、输出和错误。运行可以取消；所有可执行路径都在等待人工确认时，流程进入等待状态。失败后可以从选定失败节点创建重试运行，已有通知、文件修改等操作不会被撤回，重试前应确认是否允许重复执行。

| 现象 | 检查方法 |
| --- | --- |
| 保存提示 JSON 无效 | 检查双引号、逗号和括号；引用必须是字符串值。点击格式化辅助检查，原文不会因格式错误被覆盖。 |
| 提示节点名称重复 | 同一工作流内各类型组件都不能重名。改名后再次保存。 |
| 提示节点无法从入口到达 | 检查开始节点到该节点的连线，或移除未使用节点。数据变量组件不受此项校验限制；其他组件仍必须能从入口到达。保存校验发现错误时，相关组件会显示红色高亮框；修正后再次保存可清除标记。 |
| 提示不允许循环 | 移除回到此前节点的连线。当前版本不支持循环。 |
| 汇合一直缺少输入 | 检查所列上游是否真的选择了连接此汇合的分支。“等待全部”需要每个上游到达，不只是画布上存在连线。 |
| 引用数据不存在或来源不唯一 | 检查实际节点 ID、字段路径、命中分支及输入是否已到达。同名字段使用 `input.节点ID.字段` 指定来源。 |
| 没有命中分支 | Agent 检查 AI 识别条件，可在最后设置明确的默认分支；Switch 使用固定默认分支。其他新版判断、人工确认和通知组件不填写分支匹配条件。 |
| AI 生成内容不符合要求 | 仅需生成的字段保留空字符串，固定值直接填写。AI 只填写生成字段，不应额外添加字段。 |
| 默认 `result` 仍为空 | 数据变量和汇合组件不会调用 AI 填值。把默认空字符串改成变量或上游字段引用。 |
| 数据变量尚未赋值 | 确保对应组件已执行，并使用 `{{组件名称.变量名}}` 区分来源；未连接的数据变量不会自动初始化。 |
| 人工确认一直等待 | 默认不超时，可手动处理或取消运行；需要限时则设置等待时长或截止时间。 |
| 一条路径失败，其他路径仍在执行 | 结束范围为“当前路径”时属于正常行为；全部路径完成后汇总为失败。 |
| AI 调用报错 | 打开“日志输出”，查看同一任务的请求对话、模型返回与错误原因。 |
| 新配置运行时没有生效 | 先确认工作流已保存，再发起新运行。历史记录对应其原有版本。 |
| 通知节点成功但没有弹出通知 | 检查操作系统通知权限、免打扰设置和通知中心。 |

帮助按钮会打开独立帮助窗体，不切换或清空正在编辑的工作流。也可从应用“帮助 → 工作流使用指南”打开本文；重复打开会回到已有帮助窗体。
