# 本地 AI Agent 实施方案

## 目标与架构

将本地 AI 从聊天工具扩展为可操作项目和文档的桌面 Agent。复用已有 llama.cpp / LM Studio / Ollama OpenAI 兼容连接和密钥存储，不另建模型管理系统。

执行链路：任务工作台 → 受信任窗口 IPC → Agent 调度器 → 模型工具调用 → 工作区工具 → 结果回传模型。任务包含工作目录、模式、模型、步骤计划、执行日志、待确认操作和生成文件。模型必须支持 `tools` / `tool_calls`，普通自然语言不会被当成可执行命令。

## 基础阶段交付

- 持久化项目：在“新建任务”旁点击“新建项目”，通过系统选择器选择或创建文件夹并命名。选择项目后，新任务沿用该目录；任务记录在项目下分组显示，支持展开/收起和任务计数，旧任务按保存的完整工作目录自动关联已有项目，或以目录名补建项目；没有有效目录的记录才归入“未分类”；重启保留项目和目录。同一真实文件夹只建立一个项目。
- 独立 Agent 页面，编程、文档和通用任务模板；任务历史、继续执行、停止、产物定位。
- 有步骤上限的多轮工具循环；每轮记录真实工具结果。长内容分页读取，上下文接近容量时生成摘要，保留最新要求和完整工具调用组，原始历史保留。
- 项目工具：目录列表、文本检索、分行读取、完整文件写入、唯一片段替换、命令运行。
- 文档工具：TXT / Markdown / DOCX / PDF / XLSX 内容提取；生成 Markdown、DOCX、XLSX。扫描 PDF 无 OCR 时明确提示；不承诺保留原 Word 排版。
- 模型可维护任务计划，用户可查看每步状态、修改前后内容、命令和输出。
- 文件写入与命令逐次确认。写入审批后再次校验文件版本，防止覆盖用户在等待期间的编辑。拒绝结果回传模型；停止立即取消请求、审批和命令。
- 任务保存在独立本地目录，重启将执行中状态恢复为已停止；继续任务不会自动批准旧操作。

## 文件与命令边界

工作目录由用户通过系统目录选择器授予。创建项目时保存该授权目录；后续用项目 ID 从主进程记录中解析路径，不接受前端传入任意项目路径。继续任务固定使用原目录；目录消失或被符号链接重定向时拒绝启动。文件工具禁止路径穿越、符号链接和常见密钥文件；跳过依赖、Git 和构建目录，限制文件体积、结果长度及遍历量。文档内容作为数据返回，系统提示要求忽略其中伪装成指令的内容。

命令在选定目录启动，但不是操作系统沙箱；确认界面明确展示完整命令及这一边界。命令有超时和输出上限，停止时终止进程组。应用不自动执行模型生成的脚本。

## 验收

用临时工作区和脚本化模型服务验证：多步工具调用、拒绝/批准、冲突保护、路径限制、文档往返、命令超时/取消、任务持久化恢复、轮数限制和接口错误。再用独立 Electron 窗口验证 IPC 和界面，覆盖深浅色及窄窗口。模拟服务验证不等于实际模型质量评测。

基础阶段未包含独立进程沙箱、MCP、语义索引与 OCR；MCP 在后续本轮实施中接入，见文末交付说明。

## 界面整理

工作台采用黑白灰中性色背景与操作按钮。左侧导航仅保留图标，悬停显示名称；新建会话和新建项目收进工作空间标题右侧，分别用编辑和新增文件夹图标表示。目录切换压缩为顶部一行，完整路径可悬停查看；项目与任务合并为一份可滚动的分组列表，项目下缩进展示所属任务，项目之间可独立折叠；选择项目后保留其他分组，方便跨项目切换。欢迎页保留四个快捷任务，输入框、任务类型和开始按钮集中在同一张卡片中。点击输入框底部的模型名称展开模型及执行上限设置，Escape 或点击外部收起。

旧后台不支持项目接口时，界面提示完全退出并重新打开 MyPlaneAgent，原始错误默认收起供排查。浅色、深色及 520 / 760 / 1280px 窗口已通过 Electron 界面检查，原有目录授权、项目任务、文件确认、命令和文档产物流程继续通过。

## 模型等待与流式进度

Agent 请求改用流式工具调用，同时兼容返回整段 JSON 的服务。界面显示每轮等待时长、思考/答复/工具调用阶段及接收字符数；思考内容仅用于判断活动，不写入任务记录。首个有效输出最多等待 10 分钟，开始输出后连续 5 分钟没有新内容才触发空闲超时，单轮总时长最多 30 分钟。内置网关的聊天转发上限留出 1 分钟余量，避免提前截断调用方的等待。外部模型服务或传输层仍可能提前结束请求。

工具调用必须接收完整结束标记并通过验证，才进入原有执行与确认流程；超时、停止和输出截断不会执行半成品工具参数。自动化验证覆盖流片段与中文解码、思考进度、空闲续期、三种超时、取消、意外断流和工具参数校验；Electron 验证流式进度后继续真实文件修改、命令与 Word 生成。

## Token 用量

统一输入区底部显示当前会话或任务累计的输入、输出和总 Token；普通聊天回复同时显示单次用量。窄窗口只显示总量，悬停可查看输入/输出明细及统计覆盖情况。用量随任务和会话持久化，继续任务与重新生成均继续累计；覆盖旧回复不会扣除之前已使用的 Token。

请求通过 `stream_options.include_usage` 要求返回实际用量，读取结束标记之后的 usage 帧，同时兼容 JSON 响应和 llama.cpp 的 timings 计数。同一请求的重复快照不会重复累加。通常在每轮生成结束后更新；服务不返回统计时显示“未返回”，部分请求缺失时标注 `*`，不根据字数估算 Token。旧记录只能恢复当时保存的计数，历史缺失用量无法补算。输入包含每次请求重发的上下文与工具内容，输出按服务返回值统计，包含服务计入输出的思考 Token。

### 目录与项目关联

直接选择工作目录时自动复用该目录的项目，尚无项目时以文件夹名建立项目。读取旧任务时，为缺少 projectId 但已保存绝对工作目录的记录补齐关联并持久化，不修改任务内容、状态、时间或原目录授权。按完整路径匹配，同名但不同路径的文件夹保持独立；目录已消失的历史也保留分组，继续执行仍需通过原有目录校验。

### 上下文压缩与继续使用

智能任务与普通聊天共用摘要机制：预计输入（含系统提示与工具定义）加预留输出达到配置容量的约 80% 时，在发送前自动压缩；输入框上方可查看预计占用、摘要与压缩次数，也可点击“立即压缩”。原始 messages / events 不删除，摘要和覆盖位置独立持久化，重启后沿用。摘要请求的 Token 使用量计入累计统计。

摘要保留目标、约束、决策、修改路径、验证事实、失败或拒绝的操作和下一步。默认保留最近完整消息组；过大的旧工具结果按有界片段摘要。最新用户要求始终保留。摘要请求不提供工具，模型返回工具调用、空摘要、被截断输出或未缩短的摘要时，不替换旧摘要；取消与错误也保留原记录。生成请求明确报告上下文超限时，最多补做一次更强压缩并重试；普通聊天已经输出内容后不会自动重试，Agent 未通过完整响应校验不会执行工具。

Agent 可用只读 read_history 按关键词检索本任务原始消息，每页最多 6000 字符；普通聊天可滚动历史或导出原文。图片原件仍在历史中，摘要只使用已有文字结论并标明图片，近期图片按原样发送；需要重新识别旧图时应再次发送。

上下文占用为估算，与服务返回的实际累计 Tokens 不同。外部服务使用应用配置的容量，应与模型服务实际设置一致；本机托管按已加载模型的每个并发槽容量计算。最新输入、图片、工具定义及预留输出本身超过容量时，会提示缩短输入或调整配置。原有 200 条聊天消息 / 300 条任务事件的数量拦截已移除；本机记录仍受现有 12 MB 文件容量限制。

验证：42 项 Agent、聊天载荷、用量和上下文自动化测试通过；Electron 检查覆盖自动/手动压缩、摘要持久化、失败与取消回退、超限重试、摘要用量统计、Agent 历史查询及原有聊天、图片、项目任务和窄窗口布局。

### 聊天与任务融合

导航统一为“工作台”，由 `LocalAiAgent.vue` 管理项目、混合历史与唯一输入框，`WorkspaceChatMessages.vue` 渲染普通聊天内容。普通会话增加可选 `projectId`，按持久化项目归类。选择“编程 / 文档 / 通用执行”并发送时，以原会话快照初始化 Agent 历史，保留图片和累计用量，并保存 `sourceSessionId` 用于列表去重；原聊天文件不删除。重复转换由后台拒绝。

Agent 新增 `chat` 模式，仅提供文本/图片对话且流式显示答复，不发送工具定义，并拒绝模型自行返回的工具调用。切回执行模式沿用同一任务 ID、项目、完整历史和压缩摘要。新会话与项目切换清空草稿附件，避免混入其他会话；最近打开的记录和空项目选择可在重启后恢复。

界面采用黑白灰中性色、图标导航、可搜索项目侧栏和底部圆角输入框。模型及执行设置收进输入框菜单，输入区下方统一显示累计 Tokens，上方显示上下文估算与压缩入口。

验证入口：`tests/local-ai-workspace.electron.mjs` 检查聊天到执行再到聊天的完整流程、无跨会话上下文混入、写入确认、项目分组与去重、原记录保留、Token 累计、流式显示、重启恢复、搜索及浅色/深色/窄屏布局。Agent、聊天载荷、用量和上下文单元测试共 44 项。


## 执行可靠性、权限与 MCP（2026-09-18）

本轮在现有工作台上增量实现 P0、P1、P2 与 P3 的基础能力。旧任务、项目和摘要继续使用原记录，未做破坏性迁移。

### 新入口

1. 工作台顶部“确认执行”按钮：展开项目权限与记忆。可选只读分析、默认确认执行、项目自动修改。自动修改需原生确认并指定相对目录，例如 `src`；不会自动执行终端、测试或 MCP，也不自动覆盖脚本和常见敏感配置。项目记忆由用户编辑，作为参考资料进入模型上下文。
2. 设置 → MCP 外部工具：选择项目，填写已安装程序的绝对路径与 JSON 参数，或远程 Streamable HTTP 地址。保存不启动；“连接”经过原生确认，发现后逐个勾选工具并保存权限。每个连接最多启用 20 个工具；仅注入所属项目的工具。
3. 输入框 → 模型与执行设置：可实测工具调用，并显示本次回报的 Token。测试只要求模型返回随机 nonce，不执行文件工具；档案保存到本机。上下文容量仍来自服务配置，可单独检测图片基础识别并恢复历史结果。任务可设置累计 Token 预算，0 表示不限。
4. 工具记录：展开查看来源、授权方式、耗时、错误码、参数或修改预览。已完成的文本写入/替换/多文件补丁可点击“恢复本次修改”，原生确认后恢复；新文件会删除，存在后续编辑时拒绝覆盖。
5. 任务状态与验证：查看目标、修改文件、成功命令记录、计划待办与脱敏审计。命令退出 0 只证明该命令成功，不代表所有需求均已验证。恢复后清除当前验证结论并提示重新检查。

### 执行策略

- 内置工具从 11 个扩展为 16 个，新增 `git_status`、`git_diff`、`git_log`、`apply_patch`、`run_test`。`apply_patch` 采用结构化多文件完整 before/after 文本；写入前统一核对基线，途中失败尝试回退并报告未恢复的路径。应用崩溃时不保证跨文件原子性。
- 所有工具经过注册表的运行时 JSON Schema 校验，拒绝多余字段、类型错误、未知工具。无效调用最多纠正一次；完整模型响应的调用结构错误也最多纠正一次。断流、截断、网络超时不按格式纠错重试；已展示的聊天输出不会重复生成。
- 相同参数和相关文件状态连续失败 2 次提示换方案，3 次暂停；相同状态第 4 次重复调用暂停；本轮累计 5 次失败暂停。步骤上限沿用 10 / 20 / 40。拒绝有副作用的操作后，本轮其他写入和外部执行也不能绕过。
- 常规工具限时 30 秒，文档工具 120 秒，MCP 调用 60 秒，终端 1–300 秒。取消信号贯通；对于同步解析依靠文件大小上限约束，协作式超时不能代替进程隔离。确认等待不计入执行超时，界面审计耗时包含确认等待。
- Token 预算按服务返回的实际累计用量，在下一次推理或摘要请求前检查。单次请求可超出剩余额度；服务没有完整用量时不能严格限额。原始历史、完整工具消息和压缩开销继续保留。
- Git 只读入口禁用外部 diff、textconv、fsmonitor 与 hooks；过滤敏感路径。`run_test` 仅接受项目 `package.json` 已定义的 test/check/lint/build 及子脚本，仍逐次确认，因为脚本可执行任意代码。

### MCP 连接与数据

使用固定版本 `@modelcontextprotocol/client@2.0.0`。默认采用 2025 兼容握手，也提供固定 2026-07-28 协议；不会使用会额外启动探测进程的自动协商模式。工具的描述和 Schema 在授权时记录指纹，并在调用前重新发现和核对。变化后拒绝调用，需要用户重新连接和授权。

外部工具不因服务声明只读而自动放行。确认卡片展示服务名称、程序或地址及实际参数；它们可能发送数据或影响项目目录外部。MCP Server 按当前用户权限运行，没有文件和网络沙箱。未启用 sampling/elicitation 自动回调。连接断开、超时、工具报错或结果未知时暂停，不自动重放提交；用户核对后再继续。

HTTP 仅允许 HTTPS，本机 localhost/127.0.0.1/::1 可用 HTTP；拒绝重定向和跨源请求。当前支持手动 Bearer Token，不提供 OAuth 登录。显式环境变量与 Token 通过 Electron safeStorage 加密，安全存储不可用时拒绝保存凭据，不能降级明文。界面只返回凭据是否存在和环境变量名。修改连接前需先断开；本轮管理界面通过移除并重新添加修改连接配置。

配置与资料存放于应用数据目录：`local-ai-mcp.json`、模型能力档案、`local-ai-agent-tasks/`。每任务审计文件为 `audit/<taskId>.jsonl`，约 5 MB 轮转并保留一份前档。审计隐藏命令正文、文件前后内容及常见敏感字段；MCP 参数仅记录字段名。任务历史和审批预览包含用户原始内容，仍是本地私有资料，并非完全脱敏文件。

### 文档与后续范围

DOCX 提取保留段落位置，PDF 保留页码，XLSX 保留工作表与行内容；按 offset 分段查询时返回对应来源位置。生成 Word/Excel 后重新打开并提取内容验证可读性，校验失败时提示文件已保存、需核查，不自动覆盖重做。

尚未加入 OCR、原始版式保真、渲染后的视觉验证、公式重算、OS/容器沙箱和真实模型任务成功率评测。能力档案分别检测工具调用和图片基础识别，不会把配置的上下文容量或模型名称当作能力验证结果。

测试使用临时目录、脚本化模型服务和真实测试进程，不代表已对用户实际模型及第三方 MCP 服务验证兼容性。Windows 进程清理需在 Windows 设备上补测。更新后完整重启 MyPlaneAgent，才能加载新的主进程和 IPC。


### 项目行快捷操作

左侧项目名称右侧提供“新建会话”和“项目菜单”两个图标按钮。新建会话清空当前草稿并沿用该项目目录；已有对话保留。菜单支持置顶/取消置顶、编辑显示名称和在 Finder/文件管理器中显示。名称和置顶持久化保存，改名不改变工作目录或会话归属。菜单独立浮层显示，避免被侧栏滚动区域裁切。


## 第二轮：能力档案与文档质量

在输入框的“模型与执行设置”中，分别点击“测试模型工具调用”或“测试图片识别”。图片检测发送两张本机生成、红色色块位置不同的 PNG，连续两次答对才标记基础通过；这不能代替 OCR、图表分析或真实业务评测。不会读取工作目录图片。模型测试仍调用当前配置的服务，因此检测本身会消耗推理 Token。

结果按服务地址和模型 ID 保存在 `local-ai-model-profiles.json`，重新打开或重启后自动展示。工具与图片结果分别保留检测时间；显示最近一次检测耗时及服务回报用量，缺失统计显示未返回或部分回报。点击“停止检测”或离开工作台会取消请求，保留原能力档案；取消可能已经消耗部分推理资源。模型权重或服务配置改变后应重新检测，同名模型并不保证能力未变化。

文档读取新增以下能力：

- `source.sha256` 标记本次原始文件版本。后续调用携带 `expectedHash`；文件变化后应从头读取。工作区工具返回项目相对路径，避免同名文件混淆。
- `nextOffset` 表示当前批次还没读完；优先按 `nextReads` 中完整参数继续，其中含版本校验。完成当前文本批次后，才进入后续页、段落、行列范围。
- PDF 每批最多 10 页，返回页总数、当前页范围和无文字页列表。无文字页可能是空白或扫描图片，明确提示不能据此声称已读懂；尚未提供 OCR。
- Word 返回段落编号，并支持 `startParagraph` 继续后续批次；不提供版式保真或图片识别。
- Excel 可用 `sheet`、`startRow/endRow`、`startColumn/endColumn` 定位，每批最多 2000 行 × 100 列，来源包含 `A1:CV1` 等范围。较宽区域先继续列，再继续后续行；公式仅读取缓存，缺少结果的单元格会列出。超过 100 个工作表需要拆分。
- 返回的来源位置最多 60 条，超出标记 `locationsTruncated`；输出 JSON 保持完整，必要时缩小文本片段并调整后续偏移，不依赖直接截断 JSON。

验证入口：`tests/local-ai-quality.test.mjs`，以及扩展后的 `tests/local-ai-extensions.electron.mjs`。这些测试验证实现和交互，不宣称用户实际模型已经通过检测。

## 输出截断恢复

模型返回 `finish_reason: length` 时，整轮工具调用均丢弃，包括看似完整的调用。Agent 在没有已展示的流式答复、上下文空间和任务 Token 预算允许时，要求模型缩小本轮工作量并重试一次；再次截断则暂停，保留历史及已完成的操作，调整后可在原任务继续。已展示部分文字的流式对话不自动重放。

历史压缩遇到截断时，丢弃未完成摘要并重试一次，要求更短的摘要，同时在推理配置及上下文容量允许范围内增加输出额度。切分历史时提前预留重试空间；连续失败或取消都保留完整历史和原摘要。重试请求和服务回报的 Token 用量照常累计。

Agent 使用“开发者 → 工作区推理默认值”的最大输出 Tokens，不再额外限制为 8192。输出上限与上下文容量是不同设置，增大输出上限会减少可容纳的输入；重试仍失败时应缩小任务，或在容量足够的前提下调整输出上限。该恢复机制不能保证所有模型都能完成长输出。
