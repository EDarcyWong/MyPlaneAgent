# MyPlaneAgent 本地 Agent 总结与实施规划

更新日期：2026-09-18。本文保留实施前基线与原规划；最新交付状态见下表，不能将后续扩展项视为已实现。

## 本轮执行结果

| 阶段 | 已实现 | 保留边界 / 后续工作 |
| --- | --- | --- |
| P0 | 统一注册表、Ajv Schema 校验、参数纠正一次、模型调用格式纠正一次、重复调用/失败预算、协作式工具超时、脱敏审计、Token 预算 | 同步解析不是硬隔离；Token 预算按服务回报计数，在下一次请求前检查，单次生成可能超出余额，缺失用量时无法严格限额 |

使用入口和验证方式见 [本地 Agent 使用说明](local-ai-agent.md#执行可靠性权限与-mcp2026-09-18)。后面的“实施前基线”用于说明本轮解决的问题。

## 定位与结论

MyPlaneAgent 已具备基础编程与文档 Agent：统一会话界面、项目绑定、多轮模型工具调用、执行确认、历史保存、上下文压缩和用量统计。下一步应先提高执行可靠性与权限可控性，再接入 MCP 扩展外部能力。

MCP Client / Server 并非编程 Agent 的必要条件。现有内置工具可以直接完成编程任务；当需要标准化接入外部工具时，MyPlaneAgent 作为 Host 管理 MCP Client 与 Server。MCP 负责协议交换，不负责推理循环，也不自动提供操作系统隔离。

官方依据：[MCP 架构](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture)、[MCP 简介](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro)。实现时核对 SDK 支持的协议版本，做版本与能力兼容测试。

## 实施前基线与缺口

| 领域 | 当前实现 | 主要缺口 |
| --- | --- | --- |
| 工作台 | 聊天与任务共用输入区；项目分组、搜索、模式切换；聊天转任务保留历史、图片与用量 | 对话和任务仍是两套底层记录，需要保持迁移与恢复一致性 |
| 模型调用 | OpenAI 兼容接口、本机 llama.cpp、流式响应、工具调用解析 | 缺少实际工具调用能力测试与模型能力档案，不能仅凭模型名称判定可执行 |
| 执行循环 | 模型 → 工具 → 结果回传；10/20/40/80/120 轮或 Token 预算模式；停止、确认、恢复历史 | 重复调用、失败预算与参数纠错均有独立保护 |
| 内置工具 | 11 个：计划、历史查询、文件列表/搜索/读取、文档读取、文件写入/精确替换、文档/表格生成、终端 | 无专用 Git、结构化多文件补丁、标准测试工具 |
| 参数校验 | 有工具 JSON Schema 声明；执行端 JSON.parse 与手工字段、路径、长度校验 | 尚未统一按 Schema 校验全部参数；声明 additionalProperties:false 不等于执行端已经拒绝多余字段 |
| 上下文 | 估算容量、接近约 80% 自动压缩、手动压缩、保留完整历史与摘要；原始历史可查询；超限时最多压缩重试一次 | 缺少独立任务事实、变更摘要与项目记忆管理；大量工具定义会额外占上下文 |
| 权限 | 目录选择授权；内置文件读取有路径/敏感文件限制；修改和所有命令逐次确认；写入前再次校验文件版本 | 尚无按项目分级授权；没有 OS 沙箱与统一命令策略 |
| 超时与审计 | 模型首输出、流空闲、总时限；命令默认 60 秒、最多 300 秒；输出上限 32000 字符；工具事件与退出码 | 缺少所有工具统一时限、耗时、授权依据、统一错误码、独立审计日志 |
| MCP | 当前 Agent 未接入 MCP Client，也没有 Server 管理与调用路由 | 需实现连接、发现、启停、授权、调用、取消、故障处理和结果归一化 |
| 文档 | 读取 DOCX/PDF/XLSX/文本；生成基础 Word/Excel | 扫描 PDF 无 OCR，Word 不保留原排版；缺少生成后的结构与视觉验证 |

代码入口：`electron/main/agent/service.ts`、`tools.ts`、`model.ts`、`workspace.ts`、`documents.ts`；`electron/main/local-ai-context.ts`；`src/local-ai/LocalAiAgent.vue`。

### 实施前已确认的边界

- 终端使用 `shell:true`，只是初始 cwd 设置为项目目录；shell 可以切换目录、访问绝对路径、调用网络或其他程序。
- 环境变量已采用有限白名单，但保留 HOME/USERPROFILE 等运行必需信息；这不等于禁止命令读取用户凭据。
- 内置文件工具的路径限制不会自动约束终端或未来的 MCP Server。
- 当前错误会作为工具结果返回模型，模型可以再次尝试，但没有“无效调用只纠正一次”或防循环的独立计数。
- 当前有执行记录与时间戳，不是完整的审计系统；终端结果尚未统一保存耗时字段。

## 目标架构

```text
统一工作台（项目 / 会话 / 确认 / 变更 / 用量）
                    │ 受信任窗口 IPC
Agent Host（目标、计划、模型、上下文、循环与恢复）
                    │
工具注册与调用入口（Schema、风险、超时、审计、结果大小）
                    │
权限与执行策略（项目授权、精确预览、凭据、隔离）
              ┌─────┴─────┐
         内置工具适配器   MCP 工具适配器
         文件/Git/测试   MCP Client → 已授权 Server
```

所有执行必须经过同一工具入口；MCP 不能成为绕过本地确认的旁路。工具的来源、Schema、版本、风险、超时和执行器由注册表管理。模型层接收当次可用的工具集合，解除 `model.ts` 对固定 `agentTools` 的直接依赖。

## 分阶段落地

### P0：执行可靠性与统一工具入口

1. 增加工具注册表与 Schema 运行时校验。保留工具内部的路径、版本与业务检查；Schema 通过不等于有操作权限。
2. 将校验错误返回结构化信息：工具名、字段、原因。允许模型纠正一次，仍无效则停止该尝试并明确提示；解析失败时不得执行部分操作。
3. 区分模型解析失败、参数错误、工具业务错误、权限拒绝、网络错误、超时和结果未知。只对确定未产生副作用的失败自动重试；写入或外部提交结果未知时先核对状态。
4. 重复调用检测采用工具名 + 规范化参数 + 相关状态指纹；建议相同状态下重复失败两次提示调整策略，三次暂停。文件已变化、受控轮询等情况区别处理。
5. 为每一步设置时间和输出预算，为任务设置步骤与失败预算，贯通取消信号。
6. 补齐记录：调用 ID、来源、参数摘要、开始/结束/耗时、授权方式、结果状态、命令退出码及用量；敏感值脱敏。

验收：畸形 JSON、漏字段、未知工具、多余字段不执行；纠错次数有上限；重复失败不耗尽全部步骤；取消后无孤儿子进程；原有工作台、文档、压缩和项目测试持续通过。

### P1：项目权限与编程工具

1. 提供“只读分析”“确认执行”“项目自动执行”三种项目策略。默认沿用确认执行；项目自动执行需用户明确开启并限制到工具、目录及操作类型。
2. 专用只读 Git 工具先支持 status、diff、log；不得仅把任意 shell 命令名称识别为低风险。Git 调用关闭外部 diff/textconv 等可执行扩展，并限制参数。
3. 增加 `apply_patch`：多文件预览、精确匹配、基线校验、应用前统一检查，记录修改前后的指纹；恢复时检查用户是否又修改过文件。
4. 将标准测试/构建与任意终端命令分开。项目脚本本身可以执行任意代码，只有受信任且在已验证隔离环境内的测试任务才能自动运行。
5. 隔离可用性按平台检测和展示。未建立 OS/容器隔离时，任意终端命令继续逐次确认；命令黑名单只是辅助，不能承诺阻止系统目录访问。

验收：默认策略不降低现有确认要求；无法靠改工具名、shell 嵌套或测试脚本名获得自动执行；多文件失败不会静默留下未报告的部分修改；用户并行修改不会被恢复操作覆盖。

### P2：本地 MCP 接入

1. 在 Electron 主进程建立 MCP 管理器，使用经过版本验证的官方 SDK；首期支持本地 stdio，配置程序路径、参数、项目范围和显式环境变量。
2. 展示 Server 身份、版本、来源、工具和权限；安装与启动外部程序属于需要用户确认的动作。优先使用已安装的固定版本，避免静默执行动态下载命令。
3. 工具发现、分页、命名映射、调用与取消均走统一注册表；处理同名工具、断开重连、工具列表变更、响应大小与进程退出。
4. 外部工具风险未知时默认确认；Server 的只读等声明只作参考，不能自行授予低风险权限。
5. MCP roots 是上下文信息，不当作隔离边界。进程文件访问和网络能力由实际运行环境限制；未隔离的 Server 明示其权限范围。
6. 未启用的回调能力明确拒绝，不让 Server 自行触发额外模型调用或越过确认。首期只实现经过验证的必要能力。
7. 只向模型注入与当前任务有关、已授权的工具定义，避免整个工具库占满本地模型上下文。

验收：本地测试 Server 能发现并调用；内置与 MCP 工具共享确认和审计；超时、断线、工具变更均有明确反馈；副作用调用不因重连被重复执行；关闭应用后清理所属子进程。

### P3：文档质量、模型适配与远程能力

- 增加持久化任务状态：原始要求、当前计划、关键决策、已改文件、验证结果、待办与阻塞；项目记忆由用户查看和编辑，不把未经验证的摘要当事实。
- 根据模型实际测试结果标记文本、图片、工具调用和可用上下文；显示自动压缩开销，支持任务累计 Token 预算。
- 文档读取保留来源文件、页码、段落或单元格位置；生成后检查文件可打开、内容结构与版式，再逐步加入 OCR、模板和公式能力。
- 本地 MCP 流程稳定后支持 Streamable HTTP，补充远程认证、凭据存储、服务地址与数据发送范围展示。
- 建立固定评测集：单文件修复、多文件重构、失败测试修复、文档汇总、长上下文续作、MCP 断线恢复。统计任务成功率、人工介入次数、耗时、用量和循环次数。

验收：压缩和重启后仍能核对原始要求；任务结束明确区分已执行、已验证与未完成；模型能力判定来自测试结果；远程请求的数据范围和目标可追溯。

## 权限矩阵

| 等级 | 示例 | 默认行为 | 自动化条件 |
| --- | --- | --- | --- |
| 低风险 | 范围内文件读取、搜索、受限 Git 状态/差异 | 自动允许并记录 | 内置策略已验证，且不涉及敏感目录或外部发送 |
| 中风险 | 普通项目文件修改、生成新文档、受控测试/格式化 | 默认确认 | 用户开启项目策略；限定工具和路径；可恢复；执行脚本需可信与隔离 |
| 高风险 | 删除、安装、任意 shell、提交外部数据、Git push、敏感配置修改 | 每次确认；明确禁止的操作直接拒绝 | 不因项目自动模式或 MCP 声明而自动放行 |

风险随内容和影响变化：修改 CI、安装脚本或大规模覆盖文档可升级风险；远程“只读查询”也可能发送敏感数据。拒绝后不得换工具绕过同一操作。

## 界面与实施边界

保持现有工作台结构，仅增加项目权限菜单、设置中的 MCP 管理、工具记录中的来源与耗时，以及可收起的变更/验证面板。高级选项按需展开，不把所有协议和运行参数堆回首页。

优先实施 P0，再进入 P1。权限与统一工具入口稳定后实施 P2，最后按评测结果扩展 P3。已有会话、项目、确认、用量和压缩功能继续复用；不为接入 MCP 重写现有 Agent，也不要求基础文件工具必须迁到外部 Server。


## 第二轮进度：模型能力与文档分段读取

- 模型能力按服务地址和模型分别保存，工具/图片检测互不覆盖；面板展示各自时间、最近检测耗时、Token 回报及缺失情况。取消不会覆盖上次能力结果，多窗口并行检测不同能力时合并结果。
- 图片检测生成两张不同的随机 4×4 色块 PNG，模型必须根据图片连续回答位置；不发送项目图片。基础通过不表示 OCR、图表理解或复杂文档任务达标。
- 文档工具返回结构化来源、文件 SHA-256、nextOffset/nextReads。继续读取携带 expectedHash，文件变化时拒绝混合版本。PDF 明确报告无文字页和可能需要 OCR；Word 支持段落批次；Excel 支持行列分段和精确单元格范围。
- 质量回归覆盖正/负图片测试、取消与重启恢复、多窗口结果合并、多页 PDF、长 Word、宽/长 Excel、公式缓存缺失、文档修改冲突与返回长度。真实模型成功率评测、OCR、视觉排版检查和系统隔离仍是后续项目。
