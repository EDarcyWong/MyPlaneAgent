# 能力模块管理

入口：**设置 → 能力模块**。管理页按六个阶段展示 18 个核心模块，支持阶段筛选、接入方式筛选、关键词搜索及依赖跳转。

## 六阶段分类

| 阶段 | 核心模块 |
| --- | --- |
| 对话状态管理 | 目标与约束提取、状态来源与上下文选择、会话持久化与状态快照 |
| 消息理解与路由 | 消息意图识别、任务消息路由、必要信息澄清策略 |
| 分步执行与工具筛选 | 任务规划与步骤拆解、步骤执行与进度控制、能力注册与工具筛选 |
| 验证与错误恢复 | 工具调用与参数校验、任务完成检查、失败恢复与停滞检测 |
| 长对话与模型适配 | 上下文预算与压缩恢复、模型协议与容量适配、任务历史与经验记忆 |
| 全链路评测与加固 | 独立回归与对话回放、代码隔离与资源限制、版本发布、评分与回退 |

六阶段的 18 个模块均已接入，分为可升级策略与受保护内核：

- **可独立升级（12 项）**：目标与约束提取、状态来源与上下文选择、消息意图识别、任务消息路由、必要信息澄清策略、任务规划与步骤拆解、能力注册与工具筛选、任务完成检查、失败恢复与停滞检测、上下文预算与压缩恢复、模型协议与容量适配、任务历史与经验记忆。各自拥有版本库、接口校验、验收集、反馈、优化和回放记录。
- **共用实现（0 项）**：消息意图识别现已独立，旧目标提取版本库继续保留；旧版本中的意图规则不会自动迁移至新的意图模块。
- **应用内置（6 项）**：会话持久化、步骤执行、调用校验、回归评测、隔离运行、版本发布。这些受保护内核可运行检查、保留报告和查看历史源代码；内核代码更新随应用发布，不能由候选策略改写自己的验收或权限规则。
- **待实现（0 项）**：当前目录暂无此状态；保留筛选项供后续新增模块使用。已接入不等于所有复杂任务场景均已完善。

权限、持久化、沙箱、验收和发布边界另标记为**内核保护**。内置文件的内容指纹用于识别实现版本，不作为质量分数。带有未保存代码或策略时，管理页阻止切换模块，并提供放弃修改入口。

模块目录由应用拥有的清单注册。所有新界面操作均携带 `moduleId`；后端只允许已注册的独立模块执行版本操作。未知模块、共用模块和内置模块的修改请求会明确拒绝，不会误用其他模块的版本库。增加新的独立模块时，需要注册其运行管理器、接口与独立验收集，不能只添加一个分类卡片。

应用内核负责持久化、权限、执行证据、沙箱、评测和版本发布；策略模块提供有边界的状态、规划、筛选、验证和恢复建议。模块代码保存在用户数据目录，可以独立生成、编辑、测试和切换，无需重新编译整个应用。改变内核接口或新增底层能力仍需要应用更新。

## 使用

「全部模块」页提供**六阶段验收与对比 → 一键评测**。评测固定各策略开始时的版本，运行十二项策略的独立案例与历史反馈，并汇总六项内核检查；并发点击会被拒绝。每份报告包含六阶段明细、失败原因、耗时、版本与评测集指纹，永久追加到 `ability-modules/acceptance/`。应用或评测集变化时界面提示不可直接比较分数。

此入口是本地确定性回归，不调用真实模型，不统计模型费用，也不代表真实任务成功率。

另有「真实模型场景评测 → 评测当前模型」：固定运行六道场景题，覆盖连续修改、任务切换、工具顺序、失败后完成判断、长消息约束和发布判断。使用当前模型及连接配置，温度为 0、关闭思考和工具，每题最多 512 输出 tokens（还受服务配置和容量限制）、限时 45 秒。题目用固定 JSON 预期评分，格式错误也算失败，不由模型自行评分。该入口可能产生 API 费用。

模型报告保存到 `ability-modules/model-evaluations/`，包含题集指纹、模型名称、答案、预期、失败原因、耗时及服务返回的 Token 用量；缺失用量显示未知，不计算货币费用。可停止，退出中断后不自动重跑，历史报告可对比。这里测量模型自身答题表现，不经过完整 Agent 工具执行链，也不自动生成反馈、优化或发布能力代码。完整任务成功率及真实安装器升级/重装实验仍需另行验证。

「同题对照评测」对六道题分别运行原始组和增强组，共十二次题目请求，逐题交替先后顺序。两组固定同一连接、模型、温度和输出上限，增强组增加由上下文选择、目标约束提取、意图识别、规划和历史记忆五个实际模块生成的参考。原始题目保持一致，预期答案仅用于最终评分，不传入模块或参考资料。模块版本及源码在评测开始时固定，沙箱运行不写入线上反馈、不触发优化、不隔离或切换线上版本；异常计入增强组失败，不偷偷改用基线。

报告保存组别、五个模块的版本与哈希、输出轨迹；界面显示分组通过数、耗时、Token 和配对题目的改善/退步数。未完成的对照不作完整结论。该实验只衡量五个模块对题目理解的辅助效果，不代表十八个模块或完整 Agent 执行链有效；参考资料增加输入 Token，需结合开销及至少三次重复实验判断，不能仅凭单次分数自动发布。

1. 在模型服务中配置并选择模型。日常状态处理运行本地模块代码，不增加模型请求。
2. 进入「对话状态管理 → 目标与约束提取」后，「版本与评测」可以查看代码、对照父版本、编辑后保存新版本、运行测试、查看全部历史评测、记录 1–5 星体验评分。
3. 「测试并使用」会重新执行当前全部回归案例，通过后切换。每轮对话中模块首次使用时固定其版本，后续调用沿用；下一轮采用新版本。故障隔离仍可触发基线回退。
4. 「问题与优化记录」可以提供可复现的用户消息序列和最后一条消息的预期意图。运行异常也会自动记录。所有问题均加入后续回归测试。
5. 点击「分析问题并优化」，或者等待达到自动触发阈值。优化使用当前模型服务，发送问题样例和当前模块代码，可能产生服务调用费用。

默认开启自动分析和择优发布：累计 **2 个不同的未处理问题**触发；每日最多 **3 次**（UTC 日期），每次输出最多 **4096 tokens**，总时限 **120 秒**。实际输出上限同时受模型服务设置约束。可以关闭自动分析、关闭自动发布或修改预算。

## 改进流程

根因分析与候选代码由一次模型请求返回。根因分为模块、模型、工具、信息不足；仅模块问题生成新版本。生成格式错误、取消、超时和连接失败均保留任务记录，保持当前版本。

候选与原版分别运行应用内置验收集和全部历史问题案例。内置验收集不发送给生成模型，生成代码不能修改测试、评分或发布策略。另外最多回放 8 条已保存的对话状态输入副本，记录结果变化和异常，不执行真实工具。回放的结果变化仅供检查，不能自动证明语义质量提高。

只有同时满足以下条件才自动发布：

- 当前全部回归测试通过，且通过案例数严格高于原版。
- 候选与原版使用同一评测集，发布时没有新增案例。
- 对话副本回放无运行异常。
- 自动发布仍开启，当前版本及切换修订号未改变。
- 任务未取消，未超过时间预算。

同分不自动替换。用户星级评分不绕过测试门槛。分数衡量当前测试集上的表现，不代表所有真实任务的成功率。

运行时发生超时、异常、输出结构错误、引用不存在消息等问题时，故障版本会被标记，后续默认回退到内置基线；本轮也用基线重新生成状态参考。原始聊天处理仍保留，模块不能扩大授权或宣称工具已执行。切换代码不会撤销已经发生的外部操作。

## 模块 API v1

代码为纯 JavaScript，提供同步函数 `process(input)`，不导入模块、不使用异步宿主 API。

```js
function process(input) {
  // input.messages: [{ id: "用户消息ID", text: "用户原文" }]
  return {
    intent: "new_task",
    goalMessageId: input.messages[0]?.id ?? null,
    constraintMessageIds: [],
    amendmentMessageIds: []
  };
}
```

`intent` 可为 `new_task | supplement | correction | progress | continue | cancel | question`。三个引用字段只能指向输入中的用户消息。内核检查结构和来源；状态只是参考资料，不直接执行取消、工具调用或权限变更。

消息选择由独立的 `state-context-selection` 模块执行：宿主优先收集最新消息和上轮目标、约束、纠正来源，提供最多 200 条、约 240,000 字符的原始消息候选；在容量内将最新消息与上轮关键引用设为必保留。模块选择最多 80 条、60,000 字符，省略数量明确记录；最新消息超出容量时跳过本轮模块处理并记录日志。图片仍由原聊天链路处理，模块不读取图片，不声称理解图像。聊天中的完成记录、工具结果和待办执行依据仍由现有执行器保存，不交给模块随意改写。

内置版本使用保守的规则识别，是可用的初始实现；复杂指代、隐含任务切换及细微语义可能识别不准，可通过反馈案例和候选版本改进。当前不自动判断所有语义错误：运行错误可自动检测，语义错误主要依赖用户反馈及独立回归案例。

## 上下文选择 API v1

`state-context-selection` 使用独立基线、验收集、反馈与优化提示。输入为 `{messages:[{id,text}], requiredIds, maxMessages, maxCharacters}`，输出只能为 `{selectedMessageIds:[...]}`。消息引用须来自候选，按原始时间排序、不重复、包含全部必保留引用。字符成本为 `32 + Σ(JSON.stringify(message).length + 1)`。数量、字符容量、原文映射、候选准备和参考上下文格式均由宿主保护。

界面的问题表单使用消息行号填写“必保留”和“预期保留”，最新消息自动列入必保留。预期结果必须满足来源和容量校验，随后加入此模块专属回归集。优化同时检查历史选择输入，不执行工具；仅当全部通过且严格优于旧版时自动发布。

每轮先选择上下文，再提取目标。版本分别记录为会话状态的 `selectionVersionId` 和 `versionId`。选择模块失败时仅回退自己的基线，不改变提取模块的版本；所有失败代码和报告保留。持久化模块继续由稳定内核维护，不开放自动改写存储规则。

## 任务消息路由 API v1

`task-message-router` 是第三个独立模块。输入为 `{messages:[{id,text}], intent, taskStatus, hasAttachments}`，仅当前一条用户消息；输出只能为 `{action}`。动作包括 `new_task`、`continue`、`amend`、`progress`、`cancel`、`clarify`、`respond`，模块不能自行写入任务状态、扩大权限或调用工具。路由反馈表单单独填写识别意图、现有任务状态及预期动作，使用专属验收集和真实输入副本评测。

- 明确进度查询读取最近一次执行的保存记录，不调用聊天模型，不重复工具操作。模型曾报告完成会表述为“上轮报告已完成”。
- 明确取消暂停本会话后续执行，保留已发生的操作和任务来源；不会终止独立工作流或外部后台进程。当前生成期间仍用停止按钮。
- 继续沿用任务 ID、原始目标和历史执行证据；没有目标时直接询问所需目标。
- 明确“新任务：…”建立新的任务 ID，从当前消息开始构建模型上下文，并清除旧压缩检查点；完整原始会话仍保留。
- 补充与纠正沿用当前任务；普通回答不自动恢复旧任务。

宿主强制校验明确的取消、进度、继续和新任务控制命令，错误的意图建议或候选代码不能绕过这些边界。图片消息不按孤立的取消/进度词直接处理。任务状态保存在会话的 `abilityTask`，每条回答保留 `abilityRoute`（路由版本、动作、任务 ID），升级及重启后沿用；旧会话有可靠目标引用时首次路由补建任务信息。路由模块失败独立回退并记录问题。

目前仍使用保守规则作为基线，复杂自然语言表达可能需要反馈改进。

## 新增策略模块

新增九项使用统一外形 `{messages:[{id,text}], data:{...}}` → `{result:{...}}`，但每项拥有独立 JSON Schema 与宿主不变量。详情页显示实际接口及初始反馈样例；问题表单可编辑输入、预期输出 JSON，保存后加入该模块的回归集。

| 模块 ID | 实际接入范围及边界 |
| --- | --- |
| `message-intent` | 普通聊天在目标提取后独立识别当前意图，再交给任务路由；不改写目标来源 |
| `clarification-policy` | 聊天在调用模型前根据宿主检测到的缺失项提问，如编辑项目时缺少工作目录；不声称能发现全部信息缺口 |
| `task-planner` | 聊天和 Agent 规划器接收有数量上限、依赖有序的拆解建议；真正执行仍经执行器校验 |
| `tool-selection` | 聊天先按权限过滤，再在许可候选内排序选择；Agent 规划器也使用筛选建议；最终执行继续检查权限与参数 |
| `completion-review` | 聊天对模型完成审查再检查，未解决工具错误、拒绝授权、空结果不会被策略提升为完成 |
| `error-recovery` | 聊天工具轮次和完成检查继续时决定继续、调整或暂停；不能提高宿主停滞及重试上限 |
| `context-compaction` | 控制聊天压缩触发比例和近期保留条数；原始历史、检查点与容量硬限制由宿主保护 |
| `model-adapter` | 聊天及 Agent 模型客户端实际使用受限输出预算和温度，聊天另使用工具数量限制；服务地址、密钥和协议实现仍由宿主管理 |
| `history-memory` | 聊天选择当前任务历史中的原文引用，Agent 从最近任务经验候选中选择；最多三条，不伪造记忆或跨新任务注入旧会话 |

初始策略以规则和关键词匹配为主，提供可执行基线及持续改进入口，不保证任意弱模型都能正确处理所有任务。复杂语义质量需通过真实反馈补充评测。

## 受保护内核检查

内核详情页提供「运行检查」和历史实现存档。持久化检查使用独立探针验证原子写入、旧快照和损坏文件保护；步骤执行检查验证依赖顺序和失败阻断；调用校验检查非法参数；隔离检查验证宿主 API 不可访问及死循环中断；回归检查执行所有独立模块当前验收集；发布检查核对版本指针、父版本和代码哈希。

每次检查将结果保存到 `ability-modules/kernel-checks/<moduleId>/`，保留实现版本和逐项结果。历史源代码从目录存档读取并核对哈希，只读查看。检查不会切换正在使用的策略，也不执行真实业务工具。

## 隔离与存储

Windows 默认保存位置为 `%APPDATA%\myplane-agent\ability-modules`，与安装目录、源码目录及应用版本号无关。启动时自动读取现有版本库，不会重置当前版本、策略、评分、评测或问题记录。Windows 安装器设置 `deleteAppDataOnUninstall: false`，升级及卸载重装保留用户数据。沿用同一系统用户和数据目录即可继续使用；无需迁移已有 `conversation-state` 数据。

设置 `MYPLANE_AGENT_DATA_DIR` 时，能力数据位于该自定义目录的 `ability-modules` 子目录，重装后应沿用原环境变量。界面顶部“已保存到本机”可展开查看实际路径。

`ability-modules/catalog/` 额外保存六阶段分类、模块职责、接口、依赖及内置实现的完整源代码快照：`snapshots/` 按内容指纹保存历史清单，`sources/` 按内容指纹保存完整代码，`current.json` 指向当前应用清单。同一内容不重复存档，升级增加新快照，旧快照不删除。存档只用于保留信息，不会从历史清单自动注册权限或执行旧的内核代码。

人工备份时先退出应用，再复制整个 `ability-modules` 目录；恢复时退出应用并还原到上述原路径。重新安装系统、切换系统用户、手动删除用户数据或磁盘损坏不在安装器保留范围内，应另存备份。

模块在独立 Worker 内的 QuickJS WebAssembly 运行时执行，不暴露文件、网络、进程、Electron、导入器或其他宿主函数。每个输入使用新的运行时，设置 8 MB 引擎内存、256 KB 栈、约 100 ms 中断预算，并由宿主对 Worker 设置 15 秒外部超时。代码最多 32,000 字符，输出最多 64 KB。

实现参考 [QuickJS Runtime 官方接口文档](https://github.com/justjake/quickjs-emscripten/blob/main/doc/quickjs-emscripten/classes/QuickJSRuntime.md)。这些限制用于控制执行资源，不等同于操作系统级内存配额。打包时 Worker 与 WASM 依赖解包到 `app.asar.unpacked`。

用户数据目录下的 `ability-modules/<moduleId>/` 为十二个独立策略分别保存以下记录；原有三个模块的数据路径和版本继续兼容：

| 目录或文件 | 用途 |
| --- | --- |
| `index.json` | 默认版本、策略、故障标记、切换修订号；原子替换 |
| `versions/` | 每版完整代码、内容哈希、父版本、原因、接口版本；不覆盖 |
| `reports/` | 每次评测的独立报告、源码哈希与评测集哈希 |
| `problems/` | 可复现输入、来源版本和用户期望 |
| `jobs/` | 优化进度、所用模型、分析、候选版本、回放统计与结论 |
| `ratings/` | 追加保存的用户评分 |
| `switches/` | 版本切换记录 |
| `states/` | 目标提取的每轮状态快照及消息来源，包含两模块实际版本 ID；原始会话另行保存 |
| `replays/` | 选择、路由及其他策略的实际输入副本和版本，用于优化后回放 |

默认没有版本删除或自动清理入口。数据会随使用增长，应随应用用户数据一起备份。重启后恢复已发布版本；中断的优化记录为失败，不在启动时自动恢复发布。

Agent 任务记忆另在其数据目录的 `memory-history/` 按内容哈希永久追加，`agent-memory.json` 只作为最近 100 条缓存。旧缓存启动时存档；历史查询和按任务查询可读取超出缓存的记录。缓存使用原子写入，损坏文件会报错并保留原文件，不静默清空。备份任务经验时应复制整个应用用户数据目录。
